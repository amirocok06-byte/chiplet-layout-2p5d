# 首轮 GPU 验收的解释与后续决策

本轮于 2026-10-28 在本机 RTX 4060 Laptop GPU 运行，使用冻结阶段 0 数据。
train 为 Case1/3/4/5/6（33 状态），validation 为 Case7（7 状态），
test 为 Case8/9/10（21 状态）。seed=11，100 epochs，最佳 checkpoint 为第9轮。
完整数字见 `RESULTS.md`、`summary.json`，环境和来源见 `audit.json`。

## 已确认的事实

- CUDA 版 PyTorch 2.8.0+cu126 能在本机驱动560.94上运行训练与反向传播。
- 模型21,870参数；batch=8；本次训练函数耗时约2.50秒；测试预测约2.86毫秒。
  数据投影、环境安装和其余基线拟合不属于这两个时间字段。
- PyTorch allocated/reserved 峰值19.65/24.00 MiB；当次 allocator 限额6075 MiB。
  整卡已用显存逐batch采样峰值1146.50 MiB，包含其他进程与CUDA环境占用。
  采样峰值不等同连续采样的进程独占峰值。
- 固定策略与CNN greedy均在21状态选择 `analytical-large`，均达到该标签表的
  oracle（平均regret=0）。固定策略只从训练集平均收益选arm。
- CNN+LinUCB平均regret=0.0715316，集合命中率1/21；α=0版本平均regret=
  0.074027，全部选择rl-explore。validation在{0,0.1,0.5,1}中选择α=0.5。

## 本轮对研究问题的含义

GPU部署和可复现的离线选择链路已具备。当前切分没有展示动态选择超过固定
算法的增益：测试oracle恰好在全部状态偏好同一arm。因此CNN的100%集合命中
不能归因于其学习了有用的状态差别。

LinUCB的较差结果也不宜全部归因于探索：α=0同样较差。CNN greedy使用原
六输出head，而LinUCB在冻结embedding上重新拟合线性head；后者的条件拟合、
正则化与Case迁移都需要独立检查。训练状态只有33个，上下文却有37维，
它是一个值得检查的小样本条件；这只是诊断线索，不是已证实的原因。

## 下一批实验的预注册方向

1. 按Case做外层交叉验证，给出每一折oracle arm分布，并保留固定最佳arm。
   如果某一测试折仍是单一arm最优，应单列为“固定策略已足够”的条件。
2. 在训练/验证Case上检查embedding分布、线性head拟合误差和正则化，固定
   新配置后再使用新的外层测试折。不得反复用本轮测试Case调α或网络宽度。
3. 扩充有明确来源的独立状态/Case和宏动作预算条件，检查算法偏好变化是否
   可辨识，再判断是否需要更复杂状态网络。增加seed不能增加独立状态数。

本轮保留为原始验收结果，不据此宣称状态条件化方法有效或无效。动态选择的
研究主张需要在存在可辨识偏好变化的受控条件下进一步检验。
